# “循环音乐播放器”项目（暂定名，可更改）

## 灵感来源

人们对于喜欢的音乐作品总是会循环播放。然而由于大部分音乐的结构较为完整，仅仅单曲循环会有明显的“结尾+开头”间断结构，听感不够连贯过瘾。于是为了试图解决这一问题，我注意到在一首音乐的内部结构中（如 A + B + C1 + B + C1 + C2 + D），往往会有一个或一些部分可以单拎出来实现连贯地循环播放，同时与前后各个部分都会有较好的衔接。

## 核心实现思路

仍以一首 A + B + C1 + B + C1 + C2 + D 构成的音乐举例，首先由用户导入音频文件，在可视化界面手动、精确地切割音频，由用户自己切成“开头”“中间”“结尾”三部分。这里假设用户切的分别为 A + B + C1、B + C1 + C2 和 D。保存切割后的三部分音频，便于后续长期播放需求。
接下来，在播放器界面，用户选一首准备播放的音乐，选择两种模式：循环n次和无限循环。点击开始播放后，音乐将先播放“开头”部分，再播放“中间”部分 n 次或无限次（直至用户发送停止命令，后面会说），最后播放“结尾”部分，完成并停止播放。在播放过程中，用户有三种打断选项：暂停（再次点击恢复播放）、结束循环（不会改变当前播放状态，但会舍弃掉不含当前正在播放的这一遍“中间”之后的所有“中间”循环，也就是说，播完这一遍中间后直接播放“结尾”；如果在“开头”部分就点击了此按钮，那么会在播放完“开头”后直接播放“结尾”；“结尾”点击无效）和立即退出（立即停止播放）。

## 功能需求

### 1. 切割窗口

#### 技术实现

- 两切点的最小精度为“帧边界”，无论如何都需要吸附对齐到编码帧边界。这么做的目的是无论原音频编码格式如何，都能确保切割过程不会带来额外的音质损失。
- 所谓“无损”，就是指整个流程不引入额外的有损处理。要做到不重采样、不改位深、不做二次有损编码；保留源采样率、声道数与位深。
- 切点时间戳要注意满足 0 < cut1 < cut2 < duration，避免切割失败。
- 切割以左闭右开区间 [t1, t2) 为原则，保证切分后的三段音频能连续完整拼凑。

| 格式 | 切点对齐单位 | MVP 处理方式 | 保存格式 | 说明 |
|---|---|---|---|---|
| WAV/AIFF | 采样帧 | 直接按 PCM 样本切 | WAV/AIFF 同参数 | 样本级无损 |
| FLAC | 采样帧/FLAC 帧 | 解码 PCM → 切 → FLAC 无损重编码 | FLAC | 更新 STREAMINFO 总样本数/MD5 |
| ALAC/M4A | 采样帧/AAC 帧 | 解码 PCM → 切 → FLAC | FLAC | MVP 可先不支持 ALAC 码流复制 |
| MP3 | 编码帧，通常 1152 样本/帧 | 解码 PCM → 按帧边界样本切 → FLAC | FLAC/WAV | 不复制原 MP3 码流，避免 bit reservoir 问题 |
| AAC/M4A | 编码帧，通常 1024 样本/帧 | 解码 PCM → 按帧边界样本切 → FLAC | FLAC | 避免 MP4 edit list/priming 复杂性 |
| Ogg Opus | 包边界，帧长可变 | 解码 PCM → 按包边界样本切 → FLAC | FLAC | 高级码流复制需处理 pre-skip/pre-roll |
| Ogg Vorbis | 包边界 | 解码 PCM → 切 → FLAC | FLAC | 高级复制需处理 overlap |
| AC-3/E-AC-3 | 同步帧 | 解码 PCM → 切 → FLAC | FLAC | MVP 可选支持 |
| 其他 | 不支持则报错 | 不允许静默转码 | — | 提示用户先转 WAV/FLAC |

- 所有输入文件先用 ffmpeg 解码为 PCM，之后波形分析、切点计算、切割全部基于 PCM。禁止对压缩文件做字节级切割。
- MVP 只承诺：WAV、FLAC、MP3、M4A/AAC、Ogg Opus/Vorbis 可导入并切分；其他格式明确报错。
- 为什么不复制有损码流：有损格式的起始帧可能依赖前一帧：MP3 bit reservoir、AAC MDCT 重叠、Opus pre-skip/pre-roll、编码器 delay/padding。直接复制完整帧后，片段开头可能多出前导样本，循环时产生重复或爆音；要让播放器正确跳过，需写 MP4 edit list、Ogg pre-skip、granulepos 等容器元数据。MVP 为降低风险，统一解码为 PCM 后切分，保存 FLAC；这样三段是纯 PCM 片段，播放器可直接连续推送，循环衔接最稳。

#### UI设计

- 在切割音频的窗口中显示可视化音频波形图，用户可以在上面拖动播放点和两个切点（确切地说，显示出来应该是一根线）。窗口下方同步显示三个点的时间戳（不可编辑），格式为 mm:ss.mmm。显示值即吸附后的边界时间，允许四舍五入，内部以样本下标为准。
- 用户可以通过窗口中的按钮或左右方向键来对选中的点进行微调。用户微调步长 = 1 个编码帧（F / sr秒）；PCM/FLAC 即 1 个采样帧。
- 用户可以通过按钮或空格键来快速播放/暂停，这个过程应尽可能低延迟。
- 用户可以选择将某个切点立即同步到播放点当前所处的位置。但由于播放点不一定位于编码帧边界，因此切点实际上会吸附在距离播放点最近的帧边界处。
**请注意，以上所有功能的目的均是为了用户能更精确地找准音乐中的切分位置，从而实现更好的播放效果。请你在理解此的基础上实现相应功能，不要死板、盲目。**

### 2. 播放器

#### 技术实现

- 必须实现无缝播放：无缝播放是本项目成立的前提。切割解决的是“音乐结构无缝”，播放器则必须解决“技术无缝”，二者缺一不可——若段间或循环间存在毫秒级间隙，听感便退回普通单曲循环。因此使用 sounddevice 库的 OutputStream（PortAudio 回调模式）建立一条贯穿整个播放过程的长期输出流，绝不在段切换或循环之间重启流——每次 sd.play() 或重新 open 都会引入可闻间隙。显式指定 blocksize（建议 512–2048）与 latency，不要依赖默认值。
- 生产者—消费者模型：后台线程作为生产者，根据当前播放状态从已解码的 PCM 中取块写入“有界队列”（队列满则阻塞，形成背压，内存不随无限循环增长）；PortAudio 回调线程只做"队列 → outdata"的内存拷贝，绝不执行解码、IO 或复杂运算。
- 段边界必须在样本级完成，这是最容易踩的坑：outdata 的长度 frames 与段长度通常不成整数倍，段边界几乎必然落在某个回调块内部。因此单次回调内应“从当前段取剩余样本 → 填满 outdata → 未填满则立即切到下一状态继续填”循环进行，绝不允许“填一部分剩余样本 + 补零静音 + 下一块再换状态”——后者会在每个段边界（开头→中间、中间→结尾）插入最多一整块静音。只有真正的流末尾（结尾播完）才允许补零并触发 CallbackStop。
- 循环边界的判定不能依赖“偏移量恰好归零”：由于 blocksize 几乎不会整除中间段长度，逐块推进后中间段偏移量一般不会归零。必须改用绝对样本计数（或“本次回调是否跨过了中间段的一遍完整边界”的检测）来推进循环遍数与结束循环语义，否则“结束循环”按钮会形同虚设、永不触发。回调内须能正确处理段长短于 blocksize、长于 blocksize、恰好等于 blocksize 的三种情形，不得出现数组长度不匹配。
- “结束循环”必须不丢样本地切到尾：当检测到用户已请求停止、且当前回调跨过中间段一遍边界时，应在同一次回调内把剩余 outdata 直接从中间段续接到结尾段继续填满，而不是整块静音或丢弃这块数据。暂停/恢复、立即退出同样只改变生产者的取数计划，不中断输出流、不补零。
- 段切换与循环重复都是生产者侧的取数计划，对回调透明：数据流始终连续推送，拼接处因切分已按帧边界对齐而采样点严格连续，故无任何可听缝隙。
- 预缓冲若干块抵抗启动抖动；回调取空时填静音并累计 underrun 计数用于调参，避免爆音。
- 暂停/恢复、结束循环、立即退出均通过改变生产者取数计划实现，不中断输出流。
- 播放流程：开头 → 中间×n（或无限）→ 结尾 → 自动停止。整个播放过程中用户无法拖动进度，只允许暂停或终止播放。详见“三种打断按钮”。
- 有限次与无限次共用同一条流式播放路径，不要为有限次额外采用“先 concat 出完整大数组再一次性播放”的做法（内存随 n 线性增长，且与无限路径行为不一致）。

#### UI设计

- 曲目列表：显示已切割保存的曲目。
- 模式选择：循环n次 / 无限循环。注意 n 为整数且 n >= 1。
- 音量调节：0 ~ 100% 滑动条。
- 三种打断按钮：
    暂停：再次点击恢复播放。
    结束循环：不会改变当前播放状态，但会舍弃掉不含当前正在播放的这一遍“中间”之后的所有“中间”循环，也就是说，播完这一遍中间后直接播放“结尾”；如果在“开头”部分就点击了此按钮，那么会在播放完“开头”后直接播放“结尾”；“结尾”点击无效。
    立即退出：立即停止播放。
- 播放时可以展示播放的音乐歌曲信息等，但是不要出现进度条、播放时长等和播放进度相关的设计，此播放器本身并不适合。
- 播放中切换曲目时，应先执行“立即退出”，再加载新曲目。
- 播放结束后 UI 复位到停止状态；再次开始播放从头播放。
